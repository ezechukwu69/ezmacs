# Maintaining this config

## Conventions
- One feature per file: `lisp/<cat>/my-<cat>-<feature>.el`, header `-*- lexical-binding: t; byte-compile-warnings: (not free-vars); -*-` (config files set variables of packages that aren't loaded yet, which makes the Flymake byte-compiler report false "free variable" warnings), ends with `(provide 'my-<cat>-<feature>)`.
- `modules.el` (a Doom-style `(my! :<cat> module (module +flag) ...)` block, loader in `lisp/my-modules.el`) lists the enabled modules; `init.el` loads it, then `config.el` (personal overrides). Order matters (see below). A module that errors or is missing is reported as a warning and the rest still load (`--debug-init` makes errors propagate); `M-x my-modules-report` shows state and load times.
- Packages: `use-package` with `:ensure t` by default (`:ensure nil` for built-ins). Prefer `:custom`/`:config`; keep one package (and its keys) per file.
- Keys: `(my/leader "xy" '(command :wk "label"))` for global, `(my/local-leader :keymaps 'foo-mode-map ...)` for `SPC m`. Top-level `SPC` prefixes (labels only) are declared in `keys/my-keys-leader.el`; add a new prefix there first.
- Prefix files `my-` so nothing shadows built-ins (`org-agenda`, `eglot`, ...). Never name a file the same as a package feature.
- User/machine-specific settings go through `M-x customize` into `~/.local/share/emacs-ez/custom.el`, not into modules.

## Load order dependencies
`core` (package setup) → `ui` → `keys` (provides `my/leader`, `general`) → `editing` → `completion` → `workspace` → `lang` → `vc` → `org` → `ai` → `tools`.
- Any file calling `my/leader` must come after `keys`.
- `ui/my-ui-icons` and `workspace/my-workspace-consult` reference corfu/marginalia/consult via `:after`/`with-eval-after-load`, so they tolerate being loaded earlier.

## Adding / removing things
- **Plugin:** new file + one `require` (see README). To disable one, comment out its `require`; nothing else depends on it unless noted in its header.
- **Language server:** install the binary; eglot picks it up. For unknown ones add to `eglot-server-programs` in `lang/my-lang-eglot.el` (or a new `my-lang-<name>.el`).
- **Org capture/agenda:** edit `org/my-org-capture.el` / `my-org-agenda.el`. `~/org` is `my/org-dir` (defined in `my-org-core.el`).
- **Evil on/off:** runtime toggle `C-c t e` / `SPC t e`, **remembered across sessions** (`:evil on|off` in `ui-prefs.eld`, next to the theme and font; the last toggle wins at startup). `my/evil-enabled` (customize) only decides until you have toggled once. To forget the choice, delete the `:evil` entry from `~/.local/share/emacs-ez/ui-prefs.eld`.
- **Every Evil key and its Emacs-mode key lives in one file, `lisp/keys/my-keys-table.el`**, one line per command, side by side: `(xref-find-definitions :evil "g d" :emacs "C-c g d" :doc "definition")`. It uses `my/bind` (`keys/my-keys-dsl.el`); options `:evil`, `:emacs`, `:both`, `:g`, `:leader`, `:states`, `:evil-map` + `:after` (lazy maps). Duplicate keys warn at load; `M-x my/bind-describe` prints the live table. `SPC` leader entries stay in `my-keys-leader.el` and next to their modules; `gz` cursors, surround and text objects are Evil-only. Tests: `keys/test/my-keys-test.el`.
- **Jump list = Evil's own, shared by both modes.** Evil tags commands with a `:jump` property and records the position before them from a buffer-local `pre-command-hook` (only where `evil-local-mode` is on). `my/jump-commands` tags the Emacs commands (`evil-add-command-properties … :jump t`), and `my/jump--record` does the recording where Evil's hook is absent. Like Vim, only file-visiting buffers (and `*scratch*`) are recorded, and the entry is the place a jump *starts* from, so the first `C-o` goes to the start of the last jump.
- **Leader keys must be unique, and a clash is silent.** `my/leader` keeps its bindings in load order and the later one wins with no warning (`SPC t F` was the font picker until `lang/my-lang-format.el` bound it too and the picker seemed to vanish). Before adding a `my/leader` key, grep for it: `grep -rn '"tF"' lisp`. Toggles live under `SPC t`: `l` line numbers, `w` wrap, `t` theme, `F` font, `e` evil, `f` fullscreen, `m` modeline position, `o` format on save. Per-mode `my/local-leader` keys (`SPC m …`) may reuse letters across modes.

## Updating packages
No lockfile; packages live in `~/.local/share/emacs-ez/elpa/` from GNU/NonGNU/MELPA.
- `M-x package-upgrade-all` (or `package-refresh-contents` first). Restart Emacs afterwards.
- On a fresh machine, just start Emacs: `use-package` installs everything (first start is slow; native-comp runs in background).
- If an upgrade breaks something: delete the package dir in `elpa/` (under the data dir) and reinstall, or pin an older build by copying a known-good `<pkg>-<ver>` from backup. Commit the repo often; consider snapshotting `elpa/` before big upgrades (`cp -R ~/.local/share/emacs-ez/elpa{,.bak}`).
- After upgrading Emacs itself, run `M-x package-recompile-all` and `SPC c G` (`my/treesit-install-all`) if grammars misbehave.
- **`Cannot open load file: No such file or directory, <pkg>` after adding a package** (happened with `empv`, `evil-mc`, `evil-multiedit`). Startup activates packages from the precomputed `package-quickstart.el` instead of scanning `elpa/`. `early-init.el` points `package-quickstart-file` at `<data>/package-quickstart.el`, but `no-littering` later redirects that variable to `<data>/var/package-quickstart.el`, so every install refreshed the `var/` copy while startup kept reading the stale root copy. `lisp/core/my-core-packages.el` now sets the variable back right after `no-littering` loads, so installs refresh the file startup reads. If you ever see it again: `M-x package-quickstart-refresh`, restart (a running session keeps its old `load-path`), and check which file is in use with `M-: package-quickstart-file`. Verify with `grep -c <pkg> ~/.local/share/emacs-ez/package-quickstart.el`.

## Verifying changes
Headless load check (catches syntax errors, missing requires, void variables):

    emacs --batch -l ~/.emacs.d/init.el </dev/null 2>&1 | grep -iv "^compiling\|obsolete"

Check a command exists after loading: `--eval '(princ (fboundp (quote some-command)))'`.
Note batch mode can't catch GUI-only problems (faces, fonts) — also launch Emacs normally.

## Debugging
- Diagnostics: `SPC e` (`b` buffer list, `w` workspace list, `c`/`C` consult versions). Eglot reports via Flymake; `lang/my-lang-diagnostics.el` also opts Pyright into workspace analysis (`my/eglot-workspace-wide-diagnostics`).
- `emacs --debug-init` shows a backtrace for startup errors.
- Bisect a bad module: comment modules out in `modules.el`, or halve it (disable half the categories). `M-x my-modules-report` flags any module that failed to load.
- Start clean: `emacs -Q` to confirm a problem is from this config.
- Keys: `SPC h k` (helpful), `SPC h b` (embark bindings), `C-h e` for `*Messages*`.
- Eglot: `M-x eglot-events-buffer`, `M-x eglot-reconnect` (`SPC c R`). Event logging is off by default (`eglot-events-buffer-config`); re-enable temporarily when debugging.

## Known workarounds (revisit when upgrading)
- `keys/my-keys-evil.el`: `(defvar evil-mode-buffers nil)` — Emacs 31+ globalized modes don't define it, Evil 1.15 expects it. Remove once Evil fixes this upstream.
- Corfu needs no `corfu-terminal` on Emacs 31 (child frames work on TTYs).
- `completion/my-completion-cape.el`: eglot capf is wrapped with `cape-wrap-buster`/`cape-wrap-nonexclusive`.
- `agent-shell` needs ACP adapters installed via npm (see README); command names can change between agent-shell releases (`agent-shell-anthropic-claude-acp-command`).
- tabspaces provides the workspace isolation; if buffer lists look wrong, `M-x tabspaces-reset-buffer-list`.

## lisp/ (Emacs 31 `user-lisp-directory`)
`early-init.el` points `user-lisp-directory` at `lisp/` and sets `user-lisp-auto-scrape` to nil, so at startup Emacs only puts `lisp/` and its subdirectories on `load-path` (no manual load-path code in `init.el`). `lisp/core/my-core-userlisp.el` runs `prepare-user-lisp` once Emacs has been idle 3s after startup: it byte-compiles and native-compiles files whose timestamps changed and regenerates `lisp/.user-lisp-autoloads.el` (generated files are git-ignored).
- It must run **after** init, not before: modules use macros (`my/leader`, `use-package`) that only exist once their packages are loaded; compiling earlier would turn those into broken function calls.
- `load-prefer-newer` is set, so an edited `.el` always wins over a stale `.elc`. If something acts odd after a big change, `C-u M-x my/prepare-lisp` rebuilds everything, or delete `lisp/**/*.elc`.
- New standalone libraries: put them in `lisp/custom-plugins/`; add `;;;###autoload` to commands that should work without an explicit `require`.

## Compile hygiene
- Modules are loaded by `(my! ...)` in `modules.el`, which quotes the list and requires at runtime, rather than by separate top-level `(require ...)` forms: the byte-compiler *evaluates* top-level `require`s, so compiling a file full of them (e.g. under Flymake, which runs `emacs -Q`) would load and run every feature file and fail.
- `my/leader` / `my/local-leader` are plain functions for the same reason (general's definer macros do not exist in an isolated compile).
- File headers carry `byte-compile-warnings: (not free-vars unresolved)`: modules set variables and call functions of packages that are not loaded when a single file is compiled in isolation.
- `elisp-flymake-byte-compile-load-path` is set to the real `load-path` (core/my-core-modern.el) so `require`s resolve.
- **Docstrings stay within 80 columns, and use `\\='` for a literal quote.** Startup compiles changed files in the background (`my/prepare-lisp`, 3s idle, output in `*Compile-Log*`) and Flymake compiles the buffer you edit; both run the byte-compiler's docstring checks, so a docstring line over 80 columns is reported as `Warning: docstring wider than 80 characters` every time that file is compiled (it was what `lisp/my-modules.el` showed). A bare `'sym` inside a docstring warns the same way; write `\\='sym`. Also `checkdoc`-clean: mention each `&rest` argument by name in capitals (`SPECS`) and start error messages with a capital letter.
- **Checking a file the way startup does**, without opening Emacs: `emacs -Q --batch -f batch-byte-compile lisp/<file>.el` (then delete the stray `.elc`, or let startup rebuild it), and `emacs -Q --batch --eval '(progn (require (quote checkdoc)) (checkdoc-file "lisp/<file>.el"))'`. Module files have no `;;; Commentary:`/`;;; Code:` sections on purpose (free-form header comment), so ignore checkdoc's complaints about those.
- **`Error: End of file during parsing` in `*Compile-Log*`** means the compiler read a file whose parens or quotes do not balance. It was seen once for `lisp/my-modules.el` together with `reference to free variable` warnings for a function's own arguments, which is what a truncated definition looks like. It could not be reproduced from the file on disk (clean through `batch-byte-compile`, `prepare-user-lisp`, Flymake's backend, and compiling inside the fully loaded config), so the likely cause is the file being read half-written (a save or formatter running at the same moment as the background compile) or left mid-edit. A file that fails to parse gets no `.elc`, so the error would repeat at each startup. To clear it: `M-x check-parens` in the file, then `C-u M-x my/prepare-lisp` to rebuild everything. If it keeps coming back with `check-parens` clean, capture `*Compile-Log*` and the file's modification time.

## Dashboard (`tools/dashboard`, `custom-plugins/ez-dashboard`)
- **The first paint must stay cheap.** `initial-buffer-choice` runs inside startup, so `ez-dashboard-buffer` draws only from data already in memory. Anything slow (loading ez-agents, scanning `~/.claude` / `~/.codex` chat files, asking agents for usage) belongs in `ez-dashboard--fill`, which is queued on `my/after-startup-idle` and runs only while the dashboard is visible. A test starts a fresh Emacs and fails if the first paint loads ez-agents; check by hand with `(featurep 'ez-agents)` after `(ez-dashboard-buffer)`.
- **Alignment uses `:align-to`, not counted spaces.** Page-level placement (centering, the second column, tile edges) is `ez-dashboard--to-col`; inside a section use `ez-dashboard--pad-to` (plain spaces). Never call `string-width` on a string that holds an `:align-to` space, and keep `:height` scaling off aligned lines: nerd-icons glyphs are often wider than `string-width` says.
- **Navigation order is by section, not by buffer position.** In a two-column row a plain "next property change" would zig-zag between columns, so `ez-dashboard--items` sorts items section by section; every section line carries `ez-dashboard-in`, every item an id that survives refreshes.
- **`dashboard` is the last module on purpose** (modules.el): it links to the leader key, evil, workspaces and ez-agents. Files on the command line win over it, and a new `emacsclient -c` frame gets it (`my/dashboard-initial-buffer`). Evil: it lives in motion state because `SPC` is the leader there but not in emacs state.
- **Icons keep their font by never being re-faced.** A nerd-icons glyph carries its own `:family` face; wrapping it in `propertize ... 'face` replaces that and the glyph renders as an empty box (the stat tiles did exactly this). Add to an icon's face with `add-face-text-property`, and propertize only the text around it. A test checks tiles and titles still name the icon font.
- **Run tests with `load-prefer-newer`.** The startup pipeline leaves `.elc` build output next to the sources (git-ignored); a bare `emacs -Q` loads a stale one over the `.el` you just edited, which makes a fix look broken. Your real config sets it already.
- **Tests:** `emacs -Q --batch --eval '(setq load-prefer-newer t)' --eval '(let ((default-directory "<elpa>/")) (normal-top-level-add-subdirs-to-load-path))' -L lisp/custom-plugins/ez-dashboard -L lisp/custom-plugins/ez-agents -l lisp/custom-plugins/ez-dashboard/test/ez-dashboard-test.el -f ert-run-tests-batch-and-exit`. To look at the layout without touching real state, run `emacs -nw -Q` in tmux with fixture data (see the tests' `ez-dashboard-test--with-data`), never a second copy of the full config: its idle queue would reattach your real tmux agents.

## Modeline (`ui/modeline`, `custom-plugins/ez-modeline`)
- **The bar is a face attribute, not a character.** Bottom: `:overline` on `mode-line` / `mode-line-inactive`; top: `:underline (:color C :position t)` on `header-line` / `-active` / `-inactive`. Selected and unselected windows get different colours because those are different faces. It cannot be checked in batch or a terminal (they do not draw overlines): look at it in the GUI.
- **Faces are set directly and saved first**, never through an overlay theme: `my/select-theme` disables every theme in `custom-enabled-themes` and uses `(car custom-enabled-themes)`. `ez-modeline--on-theme` (on `enable-theme-functions`) recomputes them; turning the mode off restores the originals.
- **`:box` line widths cannot be 0.** `(VERTICAL-LINES . HORIZONTAL-LINES)` must both be at least 1; the padding is `(1 . N)` in the background colour. Right-alignment uses an `:align-to` space, so segments must not rely on `string-width` of wide icons.
- **Evil would strand buffers.** `evil-refresh-mode-line` `setq`s `mode-line-format`, copying the global value into every buffer, so a later top/bottom move would not reach them. While the mode is on that function is advised to only request a redraw, and installing clears buffer-local copies that are `eq` to our own format (intentional `nil` locals, like the dashboard's, are untouched).
- **`format-mode-line` returns "" without a live display** (batch). Three tests need one and skip themselves headless; run the suite in a terminal Emacs under tmux to run them: `emacs -nw -Q --eval '(setq load-prefer-newer t)' -L lisp/custom-plugins/ez-modeline -l lisp/custom-plugins/ez-modeline/test/ez-modeline-test.el --eval '(ert-run-tests-batch "^ez-modeline")'` (log `message` output to a file; the echo area is not readable).
- **Other packages:** `process` and `misc` render `mode-line-process` and `mode-line-misc-info` (so `global-mode-string` entries from org-clock, display-time, battery ... appear); flymake and eglot have their own segments, so their stock entries are listed in `ez-modeline-misc-exclude`. A new package that should not appear twice goes there too.

## Performance notes
- Tree-sitter is Emacs-native (31+): `lang/my-lang-treesit.el` sets `treesit-enabled-modes` (via `setopt`, its setter fills the remap) and `treesit-auto-install-grammar` (`ask`). The `treesit-auto` package was removed: its global mode probed every grammar on each file open (~3s). Grammars live in `~/.local/share/emacs-ez/tree-sitter/`; `SPC c G` installs all missing ones.
- `core/my-core-performance.el` holds global tuning and the large-file guard: buffers over `my/large-file-threshold` (512K) switch off the modes in `my/large-file-disabled-modes`; Eglot is skipped and otherwise starts on an idle timer so opening never blocks. Add expensive new minor modes to that list.
- Prefer `:hook`/`:commands`/`:defer` over `:demand t` for new packages. Avoid `diff-hl-flydiff-mode` and indent-guide packages (re-render on every edit).
- Profile slow opens: `M-x profiler-start RET cpu`, open the file, `M-x profiler-report` (expand with `E`). For startup: `emacs --debug-init` and `M-x emacs-init-time`.

### Symbols
`lang/my-lang-eglot.el`: `g0` (and `gO`, `SPC s i`, `SPC c S`) browse the symbols of the current buffer with Consult (`my/symbols-buffer`: Eglot's document symbols, else the mode's imenu; the index is rebuilt first, because imenu stops rescanning buffers over 60KB). `SPC s I` and `SPC c s` browse workspace symbols (`my/symbols-workspace`: the language server's project-wide search while you type, else the imenu of every open buffer of the project). `g0` replaces Evil's `evil-beginning-of-visual-line` in normal and visual state; that motion keeps `g0` only in Evil's motion state and is otherwise `M-x evil-beginning-of-visual-line` (rebind it in `lang/my-lang-eglot.el` if you miss it). Narrow by symbol kind with the key shown in the prompt.

### Typing and editing
`core/my-core-performance.el`: no blinking cursor, `long-line-threshold`/`syntax-wholeline-max` 1000 (minified lines), line-number width never recomputed, Flymake/Eglot/Eldoc wait for a pause in typing (1.0s / 0.5s / 0.4s), Consult async input throttled. Tune those values there if feedback feels late.

### Markdown
`lang/my-lang-markdown.el`: `markdown-mode` for editing (bullets • ◦ ▪ ▫, hidden-markup toggles on `SPC m t`/`u`) and the `markdown-preview-mode` package for the preview: `SPC m p` serves a live-updating page and shows it beside the source in an xwidget WebKit window (external browser when Emacs has no xwidgets). It needs a converter on PATH, the first found of `cmark-gfm`, `comrak`, `pandoc` (`brew install cmark-gfm`); the page loads its CSS/JS from the web. There is no custom renderer in the config any more. Updates follow your typing after `markdown-preview-delay-time` (0.3s; the package default is 2s) of idle, and the converter only runs after the buffer actually changed.

#### Installing the preview's requirements
The preview shells out to a Markdown converter; without one `SPC m p` stops with "No Markdown converter found". Install one (the config uses the first found, in this order):
```sh
brew install cmark-gfm   # smallest, GitHub-flavoured (tables, task lists, strikethrough)
brew install comrak      # alternative GFM renderer
brew install pandoc      # heaviest, most formats
```
Check with `which cmark-gfm` (or `comrak`, `pandoc`). Emacs only sees what was on PATH at launch plus the shell-environment refresh (`M-x my/shell-env-refresh`), so after installing run that, or restart Emacs. Other requirements: the `markdown-preview-mode` package (auto-installed by `use-package`; `M-x package-install RET markdown-preview-mode` if it is ever missing), an Emacs built with xwidgets for the side window (`(featurep 'xwidget-internal)` should be `t`; otherwise it opens your browser), and an internet connection, because the page loads its CSS/JS from the web. To use another converter, add it to `my/markdown-converters` in `lang/my-lang-markdown.el`.

### Startup
Measured as CPU time of `early-init.el` + `init.el` + the startup hooks (the profiler does not sample in batch mode, so time `require`s and hooks by hand with advice). What was found and fixed:
- **`my/leader` is queued** (`keys/my-keys-leader.el`). Each `general-define-key` call with `:keymaps 'override` over five Evil states costs ~12ms and there were 40 of them (~0.5s). During startup `my/leader` only collects its arguments; `my/leader-flush` (`after-init-hook`) defines them in one call, same order and same bindings. After startup it binds immediately, so `:config` bodies of deferred packages and hot-reloaded files work unchanged. Always call `my/leader` with key/definition pairs only (no keywords).
- **Shell environment: cached at startup, refreshed in the background** (`core/my-core-environment.el`). A login shell takes 0.3-1.5s to answer, so startup reads `~/.local/share/emacs-ez/shell-env.eld` (mode 0600, holds the API keys) and never waits. Five idle seconds later a login shell is queried asynchronously (started from Emacs's original `initial-environment`, so stale values cannot echo back) and PATH, MANPATH and the API keys are updated, added or removed, and the cache rewritten; a message appears only when something changed. Only the very first start, with no cache, asks the shell synchronously. `M-x my/shell-env-refresh` runs the refresh on demand. Add variables to `my/shell-env-variables`.
- **`package-quickstart` plus `package-activate-all`** (`early-init.el`, `core/my-core-packages.el`). Quickstart is one precomputed file instead of scanning 80 package directories; `package-initialize` is not used because it also parses the archive indexes (6000+ packages, ~0.13s). They are read when something is installed or `list-packages` runs. If `package-quickstart.el` ever looks stale, `M-x package-quickstart-refresh`.
- **Everything is deferred by default** (`use-package-always-defer t` in `core/my-core-packages.el`). A `use-package` form loads its package only when a command, hook, mode, key or file type needs it; a package that must be active from startup (a global mode switched on in `:config`) says `:demand t`. Packages tied to opening files use `(my/load-when-file-opened 'feature [PREDICATE])` in `:init`: yasnippet and apheleia load when the first code/text file opens, diff-hl when the first file under version control opens, envrc on the first file. They go through the idle queue, so opening the file never waits. With no file open none of them is loaded. Built-in libraries follow the same rule (ibuffer, ibuf-ext load on first use). To check a change, snapshot the loaded features, enabled modes and leader keys before and after, as done when this default was introduced.
- **Post-startup work goes through the idle queue** (`my/after-startup-idle`, defined in `core/my-core-packages.el`). Idle timers run to completion, so a dozen of them (each 0.1-1s) froze the keyboard for ~3.5s right after startup. Queued tasks run one at a time, only after 0.4s without input, with a 0.3s gap between them, and wait again if a key is pending; the longest single task is ~0.4s (which-key, `prepare-user-lisp`). Queued: which-key, envrc (both first), yasnippet, diff-hl, apheleia, the GC-threshold restore, `prepare-user-lisp`, `ez-agents-restore`. Never add a bare `run-with-idle-timer` for startup work; call `(my/after-startup-idle #'fn)`, or pass `t` as the second argument to go first. org-roam (~1s to load and sync) loads on first use or when a file under the roam directory is opened, and tree-sitter grammar sources (~0.8s) register only when you run `treesit-install-language-grammar`. Their keys are defined outside `:config` and autoload the package.
- Rebuild `.elc` files before benchmarking: a source newer than its `.elc` loads uncompiled (`load-prefer-newer`) and macroexpands every `use-package` at runtime, which can double the load time. A normal session recompiles 3s after startup (`core/my-core-userlisp.el`).

## Dart / Flutter
- `dart-ts-mode` is the community package, installed from GitHub with `package-vc` (`use-package :vc`); update with `M-x package-vc-upgrade`. Grammar source is registered in `lang/my-lang-dart.el`; install it with `SPC c G` or accept the prompt. Without the grammar, files fall back to `dart-mode`.
- `custom-plugins/ez-flutter.el` is your plugin; `lang/my-lang-flutter.el` autoloads its commands and binds `SPC m s/q/r/R/d/e/b` in Dart buffers. It keys sessions by perspective (persp-mode) if present; with tabspaces the key is just the project root.

## If generated folders reappear in ~/.emacs.d
- A running Emacs started before a path change keeps its old paths (and `M-x load-file init.el` does not re-run `early-init.el`): restart it.
- Async native-compilation spawns child Emacsen that ignore our paths; `early-init.el` sets `native-comp-async-env-modifier-form` so they use `~/.local/share/emacs-ez/native-comp-home/` instead. Any new process that loads packages the same way needs similar treatment.

## Org calendar (org-timegrid)
`org/my-org-agenda-ui.el`: `SPC o C` opens the SVG week calendar (needs an Emacs with SVG; GUI). It reads events from `org-agenda-files` (timed active timestamps) and writes new ones to `~/org/calendar.org`. The week buffer starts in Evil *emacs* state so its own keys work (`n`/`p` select, `t` time, `e` rename, `d` remove, `b`/`f` day/week, `j` jump, `.` today, `C-h m` for all). The regular agenda is left exactly as org ships it. An optional read-only day strip for the agenda is off by default (`my/org-agenda-day-strip`, toggle with `M-x my/org-agenda-day-strip-toggle`); when on, two advices make it show today and only appear when the agenda range includes today. `SPC o g` is a grouped open-task view (org-super-agenda groups apply only to that command).

## Popups
`workspace/my-workspace-popups.el` uses popper: buffers matching `popper-reference-buffers` (names or major modes) open as a bottom popup, grouped per tabspaces workspace. To make another kind of buffer a popup, add its name regexp or major mode to that list; `SPC b P` toggles one buffer between popup and normal.
- **`SPC "` (`my/popper-cycle`) and `SPC '` (`my/popper-toggle`) do not use popper's own lists.** popper files a popup under whichever tab is current *when its bookkeeping runs*, so a popup open in workspace A was re-filed under B the moment you switched to B (cycling in B showed A's popups and A lost them), and popups it had not yet seen on screen never joined the cycle. Our commands read the windows actually showing and keep a stable per-workspace ring. Which popups a workspace owns is asked of tabspaces (`tabspaces--local-buffer-p`: the workspace's own buffers plus the shared ones in `tabspaces-include-buffers`, here `*scratch*` and `*Messages*`), so another project's terminal or Eglot log that was never shown here is not offered. Without tabspaces, `my/popper--home` (popup buffer -> the workspace it was last shown in, set from `window-buffer-change-functions` and at every command) is the fallback. Internal buffers (names starting with a space) are never cycled. A lone popup stays open rather than being hidden.
- **Testing this needs a real tab.** `lisp/workspace/test/my-workspace-popups-test.el` (run line in its header; use `load-prefer-newer`). In batch popper's popups are bottom *side windows*, `popper--bury-all` leaves some up, redisplay hooks never run (so the tests call `my/popper--note-homes` after showing a popup), and a bare `tab-bar-new-tab` with a popup selected leaves the new tab showing that popup: use the tests' `my-popups-test--new-tab`.

## Terminal (Ghostel)
`tools/my-tools-terminal.el`: Ghostel + evil-ghostel + consult-ghostel. The native module (libghostty) is downloaded once to `~/.local/share/emacs-ez/ghostel/` (`M-x ghostel-download-module` re-fetches it, `ghostel-module-compile` builds from source with zig). In full-screen TUIs `ESC` goes to the app; `C-c C-r` toggles that, `C-c ESC` is a one-shot switch to normal state.

## Housekeeping
- `~/.emacs.d` holds config only. Generated state lives in `~/.local/share/emacs-ez/` (`elpa/`, `var/` history/backups/org-roam db, `etc/`, `custom.el`) and `~/.cache/emacs-ez/eln-cache/`; paths are set in `early-init.el` (honours `XDG_DATA_HOME`/`XDG_CACHE_HOME`). Backups and auto-saves go to `var/backup` and `var/auto-save` (never next to the file). Delete `var/` to reset state, the cache dir to force recompilation.
- Back up `~/org` separately; nothing in this repo stores notes.
